# AudioClone Studio 训练工作台与推理试验设计

## 状态

2026-09-17 用户已确认。本设计同步修改 AudioMiner 与 voice-pipeline，升级通用训练模块协议，并重构训练工作台。实现前必须再制定分任务实施计划。

## 目标

把当前按后端阶段创建、但内容没有联动的训练页签，改为三个稳定的用户工作页面：

```text
训练配置 → 候选试听 → 推理试验
```

同时保证：

1. AudioMiner 不导入训练或推理实现，也不加载 Torch。
2. GPT-SoVITS 与未来训练框架继续通过显式配置的独立 Python 子进程接入。
3. 训练数据不再在通用 GUI 和协议中写死为 `dataset.list`。
4. 自动评测只产生候选；只有人工晋升的最终模型可以进入自由文本推理。
5. UI 保持简洁、三语一致、字号层级明确，并避免滚轮误改训练参数。

## 不在本次范围

- HTTP、WebSocket、流式 PCM 或常驻推理服务。
- 未晋升候选的自由文本推理。
- 在 AudioMiner 进程中导入训练模块或加载模型。
- 多任务并行训练、晋升或推理。
- 为每种训练框架编写专用 GUI 页面。
- 自动裁决或自动晋升候选。

## 1. 视觉层级

### 1.1 侧栏

“工作区”是侧栏顶层标题：

- 字号大于“素材挖掘”和“训练”；
- 使用白色粗体；
- 与两个业务入口保持清晰的垂直间距；
- 侧栏进入窄屏模式后隐藏，避免挤压图标导航。

“素材挖掘”和“训练”使用相同字号与字重。当前入口继续使用绿色底边表达选中态。

### 1.2 全局字号

界面只保留以下文字层级：

- 页面标题；
- 区块标题与侧栏顶层标题；
- 普通正文、表单标签和页签；
- 辅助说明、状态和日志。

同级控件不得各自设置不一致字号。卡片只用于形成必要的信息分组，不把每个字段单独包成卡片。

## 2. 训练工作台

训练页面固定显示三个页签，页签不随任务状态增删：

1. 训练配置
2. 候选试听
3. 推理试验

页签使用绿色底边表示当前选择。后端的预处理、S2、S1、自动评测仍是任务阶段，不再作为顶层页签。

### 2.1 训练配置

训练配置页包含：

- 框架选择；
- 项目名称和项目目录；
- 训练数据；
- 输出目录；
- 设备和精度；
- 阶段选择；
- 参考音频、参考文本和参考语言；
- 高级设置；
- 开始、停止、阶段进度、错误与 Activity。

“高级设置”使用文字和箭头组成的折叠标题：

- 默认收起；
- 没有底边、下划线或额外白线；
- 点击标题切换展开状态；
- 不引入新的组件依赖。

训练启动时生成不可变任务 JSON。训练运行期间表单继续允许编辑，但当前任务只读取启动时的快照：

- 开始按钮禁用；
- 停止按钮可用；
- 显示“修改将在下次任务生效”；
- 当前任务完成或失败后，用户修改的值仍保留。

### 2.2 防止滚轮误修改

训练配置页中的组合框、整数框和小数框忽略鼠标滚轮的数值修改事件。滚轮事件交给外层滚动区域，因此鼠标经过字段时只滚动页面。字段仍可通过点击、键盘和控件按钮修改。

这一规则同时应用于公共配置和模块提供的高级字段。

### 2.3 候选试听

候选页始终存在：

- 评测产物出现前显示简洁空状态；
- 评测完成后显示 A/B/C 候选；
- 每个候选显示中文、日文、英文样本、文本和播放按钮；
- 同一时间只播放一个音频；
- 未选择时禁止晋升；
- 晋升前必须二次确认；
- 失败时保留全部候选和试听文件。

晋升成功事件必须包含受校验的 `promoted_model` 目录。只有该产物能解锁推理执行。

### 2.4 推理试验

推理页始终存在。即使没有最终模型，用户也可以提前配置：

- 页面内多行文本；或
- UTF-8 `.txt` 文件；
- 中文、日文、英文或 Mixed；
- 设备沿用训练配置中的设备选择。

页面内文本与 TXT 文件严格二选一。没有最终模型时：

- 显示“当前尚未挑选候选权重，无法运行推理”；
- 文本、TXT 和语言仍可编辑；
- 仅禁用“开始推理”。

推理完成后：

- 页面提供播放结果和打开目录；
- 显示约 4 秒的非阻塞小提示；
- 提示包含完整保存目录；
- 不打断音频播放和继续编辑。

输出固定写入：

```text
<项目目录>/outputs/<项目名称>/gui/<时间戳>.wav
```

时间戳文件名不得覆盖旧结果。

## 3. 模块协议 v2

协议版本从 1 升级为 2。AudioMiner 与 voice-pipeline 同步升级；协议 v1 模块显示明确的不兼容错误，不静默猜测字段。

### 3.1 框架描述

每个 framework 新增 `training_data`：

```json
{
  "kind": "file",
  "extensions": [".list"]
}
```

规则：

- `kind` 只能是 `file` 或 `directory`；
- `extensions` 仅允许用于 `file`，可以为空；
- AudioMiner 的普通标签统一显示“训练数据”；
- 选择器和存在性校验由 `kind` 驱动；
- 模块负责理解实际数据格式。

GPT-SoVITS v2ProPlus 声明 `file` 和 `.list`。未来模块可以声明目录或其他文件扩展名，无需修改 GUI。

framework capabilities 新增 `infer`。GPT-SoVITS v2ProPlus 支持：

```text
preprocess, train, evaluate, listen, promote, infer
```

### 3.2 训练任务

训练任务删除通用字段 `dataset_list` 和 `dataset_sha256`，改为：

```json
{
  "training_data": {
    "path": "D:/...",
    "kind": "file"
  }
}
```

任务同时记录当前 `module_id` 和 `framework`，用于恢复时拒绝把其他模块或框架的产物绑定到当前页面。

AudioMiner 负责：

- 绝对路径；
- 路径存在；
- 文件或目录类型与 descriptor 一致；
- 路径位于目标人项目目录内。

训练模块负责格式、内容与指纹校验。voice-pipeline 继续在模块边界内读取 `dataset.list` 并计算需要的摘要，不把格式知识泄漏回 AudioMiner。

### 3.3 推理请求

AudioMiner 在当前任务目录下创建独立推理请求：

```text
jobs/<job_id>/inference/<request_id>/request.json
```

请求至少包含：

```json
{
  "protocol_version": 2,
  "request_id": "...",
  "project_root": "D:/...",
  "project_name": "Acane",
  "model": "D:/.../promoted-model",
  "text": "...",
  "text_file": null,
  "language": "ja",
  "device": "cuda:0",
  "output": "D:/.../outputs/Acane/gui/20260917-183000.wav"
}
```

`text` 与 `text_file` 必须恰好一个非空。用户可以从项目外选择 TXT；AudioMiner 验证其为 UTF-8 后，把内容复制为请求目录内的只读输入快照，模块只接收该快照路径。请求中的所有路径因此都是绝对路径并位于项目目录内；`model` 必须与已记录的 `promoted_model` 一致。

执行命令：

```text
<module-python> -m <module-name> module infer --request <request.json> --events-jsonl
```

voice-pipeline 复用现有 `InferenceSession`、文本切分和 `run_synthesis_job`。AudioMiner 不理解模型 bundle 内部结构。

推理成功时模块发送：

```json
{
  "type": "artifact",
  "artifacts": [
    {"type": "inference_audio", "path": "D:/.../result.wav"}
  ]
}
```

## 4. 状态与恢复

同一个训练工作台同时最多运行一个模块子进程：训练、晋升和推理互斥。进程运行时：

- 当前操作的执行按钮禁用；
- 训练配置仍可编辑；
- 候选选择和推理执行锁定；
- Activity 和错误区继续接收结构化事件与 stderr。

当前会话晋升后立即保存 `promoted_model` 并解锁推理。

重新启动 GUI 后，当用户选择项目目录和项目名称时，AudioMiner 从该项目的 `jobs/*/events.jsonl` 中读取最新有效的 `promoted_model`：

- 事件必须通过现有协议解析；
- 产物目录必须存在；
- 路径必须位于项目目录内；
- 模块 ID 和 framework 必须匹配当前选择；
- 无有效产物时保持推理按钮禁用。

不得通过猜测 `models/<项目名称>` 等模块内部目录恢复模型。

## 5. 错误处理

- descriptor 不合法或协议版本不兼容：模块连接失败并显示明确错误。
- 训练数据类型或扩展名不匹配：开始按钮禁用并显示字段错误。
- TXT 不存在、不是 UTF-8 或与页面文本同时设置：推理按钮禁用或返回明确错误。
- 最终模型缺失或逃出项目目录：推理保持锁定。
- 推理失败：保留文本、TXT、语言和可恢复推理缓存；错误显示在推理页和 Activity。
- 推理产物路径或类型不合法：按协议失败处理，不交给播放器。
- 小提示只用于成功结果路径，不用于隐藏错误。

## 6. 国际化

新增的页签、空状态、折叠标题、下次生效提示、推理字段、按钮、成功提示和错误摘要全部提供中文、英文、日文文案。

以下内容保持原文：

- `GPT-SoVITS`、框架显示名；
- `A/B/C`；
- 文件路径；
- `CUDA`、`FP16`、`Mixed` 等技术标识。

## 7. 验证

### AudioMiner

- 侧栏标题字号和字重层级；
- 固定三个训练页签及三语切换；
- 高级设置默认收起、无底边；
- 滚轮不修改组合框和数值框；
- 文件/目录训练数据选择与校验；
- 训练快照与运行中可编辑表单；
- 候选空状态、试听、选择和晋升；
- 未晋升时推理字段可编辑但执行禁用；
- 晋升产物解锁推理；
- 重启后从事件恢复最终模型；
- 推理请求、结果播放、打开目录和短暂路径提示；
- standalone 模式和原素材挖掘流程无回归。

### voice-pipeline

- protocol v2 descriptor 稳定且不导入 Torch；
- 通用 `training_data` 的严格解析与 GPT-SoVITS `.list` 适配；
- `module infer` 对请求字段、模型、文本来源和输出路径的严格校验；
- 复用现有推理实现并输出 `inference_audio` 事件；
- 推理失败不破坏最终模型或已有结果；
- 原 CLI 训练、评测、晋升和推理无回归。

### 最终验收

1. 两个仓库完整测试通过。
2. AudioMiner 使用真实 voice-pipeline 完成 protocol v2 握手。
3. 使用现有已晋升模型完成一次短文本协议级推理，GUI 能播放输出并显示保存目录。
4. 不生成 EXE、ZIP、模型副本或额外训练权重。
